# 52三国志 POC

一个以《三国志》武将养成为方向的纯前端游戏原型。玩家扮演一名真实武将，原有月度内政、太守自治、部队整备与跨月野战／攻城作为世界运行层保留。

## 武将人生（当前可玩流程）

- 新游戏先选势力，再选主角；旧势力存档首次进入时以原势力君主接续，不重置世界。
- 默认进入个人城景主界面：自宅、友宅、酒馆、军营、农田、市场、城墙、工坊、议政厅与驿站。进入议政厅才展示原战略地图，出征等战略指令从议政厅办理。
- 个人行动力每月100，个人行动大多即时生效。修习25点、拜访15点、酒馆20点、请领公务10点、迁居30点。参数在 `src/data/character-system.json`。
- 修习积累五维历练，每100历练提升1点基础能力，最高100。拜访增进双方亲善；酒馆赚取私金；月俸从实际已支付的城库俸禄中按比例转入私金，不再额外扣城库。
- 君主治理全势力，太守治理本城，普通武将仅查阅政务并请领公务。颁发政令不耗个人行动力，任务仍占用执行将领并预留真实城库物资。没有玩家管辖的城池由AI维持经营、集结与出征，AI不擅自消费主角的公务机会。
- 主角拥有独立私金（开局200）。个人建设每次25行动力、20历练，自费金额沿用对应城务成本，成果即时归本城，绝不扣官库金粮；不占政令或将领月度公务次数，可在AP与私金允许时重复执行。军营募兵/训练，农田开发农业/养马，市场开发商业/治安，城墙修筑，工坊制弓/锻甲。每次募兵500人，初始粮费按当月粮价折成私金一并支付，后续驻军消耗仍由城市负责。满值建设不会收费空转。
- 议政厅「请领公务 · 复命」领取限期工作目标：默认3个月（含领命当月）内完成约两次工作量，只计本人领命后在指定城池、指定项目的实际贡献。城库预留赏金，主角先自费建设，达标后回本城复命领取私金、60功勋和35历练；复命不耗AP。任务不锁住个人行动，过期不领奖、建设保留，未发赏金退回原势力；任职/城池归属变化会取消委托。进度、期限、赏金和领赏状态随存档保存，不能重复领奖。旧存档已经排定的月末公务仍按原规则执行。
- 已移除个人「申请随军」入口与行动。进攻提案系统留待后续实现；君主/太守原有权限内的出征命令及已经进行中的战役保留。
- 顶栏仅放只读资料（含近日行止）和系统菜单，声音设置收进系统。天意与全局政策收在议政厅右上月份面板内。个人城景左侧竖排工作地点，横牌宽度约为人物窗口的76%；底部居中排列自宅、友宅、酒馆，竖牌宽度较横牌高度增加10%，共用尺寸、首字装饰与边框，自宅保留暖色。驿站与待命位于右下。
- 第一队第一位将领为固定全军主帅，主帅可控制全军，非主帅只能控制自己所在部队（包括副将）；其余友军与敌军使用同一个战斗引擎的AI行动。非主帅的攻城暂由AI主帅自动下令。无主角参与的战役在后台模拟。
- 战役结束给予参战主角统帅历练50、武力历练25、功勋80。事件回执随存档保存，恢复结算不重复发放。
- 败亡不会直接结束人物生涯。本轮将被俘或失去势力的主角简化为在野，可在驿站游历并在有主城池自荐；完整俘虏/任官/人际剧情待后续设计。
- 「技艺 · 宝物」展示48项常规技艺与2项隐藏技艺、宝物簿、生卒年、历史死因及状态栏。50项技能均为预留，不产生效果；未知生卒/死因不编造，历史卒年不触发死亡。宝物提供持有即生效、同类取最高的修正结构，但暂不投放实际宝物或获取事件。

### 规则扩展接口

- `game/modifiers.js`：纯数值流水线 `(基础+固定值之和)×(1+百分比之和)×独立乘数之积`，最终取整/限幅；返回来源明细。支持条件、来源去重、同组取最高。城池/势力修正只收集一次；已经接入内政增益、个人AP消耗/成长、部队五维聚合，其他数值可逐项迁入，不改旧战斗结算公式。
- `game/capabilities.js`：身份、政务管辖、个人行动、战场控制权的统一查询；`checkRequirements`提供科技、能力、资源和授权标记的声明式资格接口。未知条件拒绝通过；占位技能不授予资格。
- `game/domain-events.js`：提交阶段事件入口，稳定业务ID去重，保存序号、已处理回执与近期日志。任务完成、战役完成、个人行动均接入。只在事务草稿内发出，界面/预览不能发事件，读档不重放奖励。以后增加事件处理应新增明确处理分支，不注册任意脚本钩子。
- `game/character-state.js`：稳定主角ID、身份衍生、角色档案、成长和月度AP；`game/personal.js`：个人事务与有限公务申请服务。`DUTY_MANDATE`仅供该服务在批准真实公务后内部使用，UI不能直接获取任意政务授权。
- 存档保存原始数据、状态与事件回执，不保存修正后的派生能力。技能槽位ID为`组名.序号`，现有编号不可重排；新增效果应独立配置，不能靠按钮文案作为规则标识。

本轮保留的简化：请领任务的审批按角色、占用与资源确定；没有概率刷审批，没有关系授予全军指挥权，没有自动升任太守，也没有技能学习和宝物获取流程。

## 本地运行

```bash
npm run build
npm run dev
```

浏览器打开 `http://127.0.0.1:4173`，开发服务器默认只监听本机回环地址，不发布站点。

## 目录

- `src/data/`：剧本、城池、武将和规则参数
- `src/js/game/`：状态、内政与战斗规则
- `src/js/ui/`：可复用表格、弹窗、通知等组件
- `src/assets/`：独立美术与音频资源
- `tests/`：规则层单元测试

存档保存在浏览器 `localStorage`。启动先显示主菜单，不会自动推进存档；选择「新游戏」进入剧本与势力选择，或「读取存档」继续自动存档／上一局快照／手动存档。游戏右上角「菜单」打开浮动系统窗口，提供存档、读档、返回主菜单与继续游戏；不会一键退出当前局面。

- 三个手动存档槽独立保存，不被自动档、新游戏或读档覆盖。覆盖已有档位需再次确认；写入失败保留原档。
- 主界面和游戏内共用读取窗口；游戏内读取需确认，读取手动档或上一局快照前会保留当前活动档。返回主菜单需确认并保存当前战略进度，之后可以继续本局。
- 战斗每次有效行动、逐格移动和攻城指令均自动保存完整局面，刷新后从检查点继续，不从第一天重开。战斗、月结或月初汇报尚未完成时仍可打开菜单，但暂禁手动存档、读档、返回主菜单，防止切换局面打断未完成结算；本月战事暂停、回到可操作的大地图后允许手动存档，包含所有持续战役。
- 正文、表格、数值使用项目自带思源黑体 CN；标题和装饰文字使用项目自带阿里妈妈刀隶体。两者通过 `src/styles/typography.css` 中 `@font-face url(...)` 从 `src/assets/fonts/` 加载，Windows/Mac 无需安装字体，运行不访问在线字体服务。标题中的罕见字回退到同样自带的思源黑体。
- 字体原始文件、版权声明与来源均保留在 `src/assets/fonts/`。思源黑体使用 SIL OFL 1.1；刀隶体按当前用户个人、本地内部嵌入用途使用，保留官方声明，不改字体文件。刀隶体的现行声明限制重新分发，因此未来公开发布或将游戏包分发给其他人之前须另行确认许可或替换，不能把非商业等同于无限制授权。
- 游戏显示名为《52三国志》，标志为本地 SVG「伍贰三国」朱砂云纹印章，四字已导出为矢量轮廓，完全不依赖操作系统字体。为兼容旧进度，内部存档与声音设置键名保留不变。

## 窗口动效与声音

- 主菜单、大地图、野战和攻城使用统一的短墨色转场；城市面板切换、通用操作窗口、确认框和人物对白有轻量开合效果。同场重绘不会反复播放转场，系统的「减少动态效果」设置会关闭这些动效。
- 两首原创本地循环曲：大地图／主菜单《江山闲赋》（约53秒），野战／攻城《旌旗动地》（约37秒）。采用程序编曲合成的拨弦、笛音与鼓声，不使用商业游戏音乐或外部采样。
- 按钮和城池点击都有短木质音效，动态生成的按钮共用同一处理器。禁用按钮与程序内部模拟的点击不重复发声。
- 浏览器需首次用户点击后启奏。主菜单「声音设置」或顶部「声音」可分别调节音乐、点击音量并总静音；设置自动保存在本机。页面切到后台自动暂停，返回后恢复；战略／战斗之间淡出淡入。
- 配置为 `src/data/audio.json`，音频为 `src/assets/audio/*.wav`，可运行 `node scripts/generate-audio.mjs` 离线重新生成。音频控制、场景动效分别封装在 `ui/game-audio.js` 与 `ui/scene-transitions.js`。

## 战略地图

武将模式不限制颁发政令总数，且不消耗个人行动力；执行将领的公务占用、钱粮费用与战场行动力仍保留。旧势力模式的指令额度代码和`commandLimitEnabled`配置保留，进入武将模式时覆盖为不限。内部剩余数仍以零为下限记录，不产生负数。

目前为 81 城地理图：以《三国志13》60 城为底，增补柴桑、云南和河西、辽西、岭南等据点。城池归属、驻军和驻留武将独立配置，允许无人驻将、太守空缺和无势力占领的城市，不自动补人或分配势力。存档载入时自动刷新地理元数据，不重置同一剧本的经营、兵力和真实武将状态。

- 拖动或方向键平移，滚轮或加减按钮缩放；“全图”返回总览。
- “九州分览”跳转区域，搜索支持城名及别名（例如徐州 → 下邳）。
- 点击城池打开浮动军府；可收起面板专注阅图。缩小时隐藏相互重叠的城名，所有城池标记仍可点选。
- 城市详情和政令位于左侧，直辖城池列表在右侧，地图工具在右下角。左上标题窗已移除，其织纹铜框样式保留为 `.ornate-map-window`，便于后续窗口复用。
- 右下「地图」切换原地图、势力、外交关系、州郡四种视图，默认不染色。外交以玩家为参照，区分我方、有效双边同盟、实际交战、未结盟与无主；同盟不传递。颜色偏好独立于存档，切换不改变游戏状态。城池归属或同盟关系变动后自动重绘。
- `src/data/strategic-atlas.json`：城市经纬度、别名、区域与双向邻接。
- `src/data/strategic-territories.json`：81 城固定的近邻控制区及共享边界；叠加底图海岸／湖泊遮罩，不染海洋和无城岛屿。仅为游戏化辖区示意，**不是精确历史疆界**。生成器为 `node scripts/build-strategic-territories.mjs`，新增城池后重新生成；也可后续替换为手绘多边形。
- `src/data/map-modes.json`：显示方案、透明度与图例颜色；`src/js/ui/map-colors.js`：独立的归属／外交到色彩投影及 SVG 层。共享地图镜头，不拦截城池点击，同组辖区隐藏内部边线；扩展新染色方案只需增加配置和取色方法。
- 扩展接口：`registerMapColorResolver(id, resolver)` 注册纯取色规则，模式配置通过 `resolver` 引用它；`createNumericMapColorResolver` 按外部阈值分档，供未来人口、兵力、粮食等热力图复用。图例的全量／选中项、色板、玩家参照和展开按钮均由 `legend` 配置驱动，不把某一种模式写死在渲染器内。
- `src/assets/map/strategic-map.svg`：独立本地底图；`geography.json` 为裁剪地理数据；`source-notes.json` 记录来源和误差。
- `src/js/ui/strategic-map.js`：地图缩放、拖动、定位与城名避让。

底图以 Natural Earth 公共领域海岸和水系为骨架，山地与汉魏黄河下游作示意，不绘现代行政边界。城址与古河道并非精确历史复原。所有素材在本地读取，无在线地图服务依赖。需要调整地形样式时，可运行 `node scripts/build-strategic-map.mjs` 离线重建 SVG，然后 `npm run build`。

## 建安元年剧本

- 时间截面：公元 196 年十一月。从主菜单选择「新游戏」后选择势力，也可在游戏内返回「主菜单」重开。
- 81座城池、25方势力、241名历史人物（含12名在野），不使用虚构占位人物。柴桑、云南、南海、郁林、合浦开局无驻留武将，仍保留既有城池归属与驻军；驻军数不受当前驻将统兵上限约束，出征时才按实际带队将领限额编军。原始编制在 `scripts/build-scenario-196.mjs`，生成 `scenario.json`、全员列传和 `scenario-notes.json` 考据说明。
- 旧版徐州存档仍保留在 `hanmo-zhoujun-save-v1`，新版按剧本 ID 保存到 `hanmo-zhoujun-save-v2:<id>`。重开前把当前局保存在同名 `:previous` 快照槽；不会迁入旧五城剧本的领土配置。
- 旧建安存档载入时会移除已撤销的17个占位人物及其任职引用，不重置月份、领土、资源和真实人物状态。主菜单读取发生数据升级时，原始存档另存为同名 `:before-menu-upgrade` 快照；历史迁移入口的 `:before-placeholder-cleanup` 等快照也继续保留。受影响的待处理出征撤回兵力，无须重开。新游戏／读取快照先建立临时恢复记录，再替换活动槽位；写入失败会回滚，回滚受阻时保留恢复记录，不静默丢弃原档。
- 城池归属、武将配置、五维及列传都在 `src/data/` 中，不嵌入页面。所有可选势力使用同一套规则；剧本考据与游戏化取舍可在选势力窗口展开查看。
- 结束本月时先完成到期任务、建立出征战役，再执行其他势力行动及来袭选择，统一推进本月各场战斗，最后由 `advanceMonth` 处理自治、月税、军粮和俸禄，递进日期后在七月收粮并刷新行动。已付战场日粮按实际天数抵扣驻军月粮，不重复收费。每月最多新发起四场 AI 战争，前两次月度推进不主动攻击玩家。
- AI 会为无人任职城调任人员，也会从连通内地向边境集结（每势力每月一次，内地留至少3,000兵、前线最多18,000兵）。集结需要武将执行且消耗其当月行动，训练与士气按兵力融合。前线兵额已满但统兵额度不足时，仍可单独调将；内地须留人、不能调走君主，迁任支付费用并占用行动，不额外增加兵力。
- 来袭玩家城池会保存为待处理军情：“出城野战”进入逐格战场，“直接守城”进入全军攻城模式，两者都由玩家指挥。玩家主动进攻时 AI 默认先野战。弃城撤退会让出城池及仓储，守将与残军有另一未被围攻的己方城池才可撤离。双方部队、兵种伤亡、军粮、行动顺序、状态及攻城进度均入档，不重复扣出征兵员、钱粮、费用或指令。
- 攻下城池后，守将撤往本势力领地或被俘；灭亡势力的武将不会凭空消失。寻访发现本城在野人才，登用可招募已发现人才与俘虏。迁任只移动武将；「输送部队钱粮」可同时或分别调拨兵力、金与粮，执行武将留在原城。
- 亲善提高友好度；友好达到 45 后可尝试缔结六个月同盟，盟约限制双方进攻。流言降低敌城民心及士气；离间降低指定非君主敌将忠诚，登用可进一步招揽邻城忠诚 ≤60 的敌将（不含盟友、君主与任务锁定武将）。劝降仅对满足城池／兵力弱势条件的敌对势力开放，成功后城池与在任武将整体归顺。以上动作均有独立窗口，签发占用指令、武将和钱，默认月底执行；失败也收费，目标失效则撤销退款。
- 己方城市可「伏兵准备」：有效期三个月，下一次防守野战的首次有效伏击增伤 25%，实际发动后才消耗。不叠加，仍须在树林／山地正常埋伏。战略规则和概率集中于 `rules.stratagems`，实际效果由 `game/stratagems.js` 处理。
- 目标为统一天下；失去全部城池且无仍在作战的远征军则本局结束。出发城失守不会把外征将领直接俘虏，远征军仍可攻取据点或撤往其他未被围攻的己方城池。顶部“天下势力”和“军府记事”提供领土、兵力、关系与近期战报，“战役簿”统一追踪玩家与 AI 的战争。

## 多将编组、野战与攻城

- 战场界面：野战地图扩大为 18 × 14，使用正方形四边格、逐列错开半格。棋盘按 18 : 14.5 的内容比例整体等比缩放适配窗口（额外半格用于错列），空余处保留背景，不为铺满宽屏而拉伸格子。攻城使用本地 `assets/battle/siege-background.png` 背景，城防、两军、军令和纪要均为独立浮窗；“收起浮窗”可查看或点击被遮住的区域。背景由内置图片生成工具生成，原始提示词随素材保存在同目录。

### 迷雾、伏击与控制区

- 野战行动力按原公式结果减半（向上取整），普通步兵约 3 点、精兵约 4 点、精锐骑兵最多 5 点。攻击／火攻的行动点成本同步缩放，保留移动与攻击组合；金钱花费不变。参数集中在 `rules.json` 的 `battle.field`。
- 同方共享即时视野，默认比部队标准行动力多一格。森林、山地中的敌军只能邻接发现，且地形遮挡后方直线视野；不通过绕路搜索“看穿”。全部地形始终可见，视野外只覆盖半透明遮罩，隐藏部队、实时兵力、行动顺序及军情。守方主据点与攻方大本营是公开目标，标记始终保留；AI 可向公开目标推进，但不利用迷雾内敌军坐标。
- `field-visibility.js` 独立负责正面错列六边距离、视线与能力扩展接口，可通过视野钩子增加侦察范围或看穿遮蔽物，不将兵种／人物特殊技能写死在界面里。
- 「埋伏」只能在树林、山地执行，结束本队当前行动，状态跨日保留。第一个普通进入邻格的敌军遭受无反击攻击并结束其本次行动；多支符合条件的伏兵按先攻顺序依次发动，目标溃散后停止。发动后解除埋伏；主动移动、攻击、火攻或回城亦解除，单纯结束行动继续潜伏。
- 「警戒移动」消耗地形移动费的 3 倍，单格费用不超过本队满行动力，因此满行动力至少可走一格合法地形。警戒不会触发或消耗敌军埋伏，邻接仍能发现伏兵，且仍受 ZOC 约束。
- ZOC 为所有存活、未回城敌军的邻接六格之并集。禁止从一格敌 ZOC 直接移到另一格敌 ZOC；允许退到非 ZOC 地块，再重新进入。路径预览只采用已发现敌军，实际每一步重验真实占位与 ZOC，遭遇新障碍或伏击立即停止，不泄露未发现单位名字或位置。
- 火攻、疑兵和挑衅均须邻接可见敌军；火矢仍是远程射击。疑兵跳过完整行动，挑衅强制逐格追击施计者并在邻接且行动力足够时攻击。双方中计使用同一个自动行动入口和普通移动／攻击规则，伏击照常逐支触发并终止本次追击；不会绕开地形、ZOC 或军粮。隐匿施计者只追至最后已知位置，死亡或回城则永久解除挑衅；进入攻城清除野战控制。新计略默认消耗 2 行动力、50 金，按双方智力判定，配置在 `rules.battle.strategies`。
- **持续状态**：`rules.battle.strategies.doubt.durationActivations` 与 `provoke.durationActivations` 控制影响的部队行动次数，默认均为 1；改为 3 即影响接下来三次行动，不是三次移动或三个战略月。每次完整行动结束统一扣一次（含疑兵跳过、挑衅受伏击或受阻结束），同次多次移动／攻击不多扣；下一日恢复行动力不会重置状态。疑兵优先于挑衅，两者共存时各消耗一次，未到期的状态保留，同种状态不叠加。
- `game/battle-statuses.js` 集中定义状态名、控制优先级、持续单位、每次行动后的重置项、阶段清除规则与添加／移除／过期接口。部队只持有可序列化的 `statuses` 字典，实例包含 `type`、`remainingActivations`、`sourceId` 及专属上下文（如挑衅目标最后位置）。旧 `doubt`／`provocation` 是非枚举兼容访问器，JSON 不双写；克隆后可通过 `initializeBattleStatuses` 恢复兼容接口。新增状态先登记定义、再在引擎实现效果，生命周期不重复散写；剩余持续次数跨存档和跨月保留。

- 军队最多 8 支部队，每队最多 3 将（`rules.army` 可调）。编组窗口明确选择主将，仅主将职位兵额决定整队兵力上限，其余将领参与能力计算而不增加兵额；兵力、伤亡、训练与士气只按部队统计，地图也只绘制部队。旧档中已经出发的合法历史编组不直接裁兵，新命令使用新限额。
- `game/army.js` 的 `aggregateAbilities` 统一处理部队和全军能力，当前五维逐项取参与将领最高值，预留上下文参数供关系／相性规则替换。`ui/army-composer.js` 复用出征与守军编组窗口。
- 野战采用正面错列四边格，地图保证守方主据点和攻方大本营。攻军任意部队进入主据点即转入攻城；守军任意部队占领大本营则攻军粮草被劫，立即败退。逐格移动先结算伏击，部队仍存活才判断占领。守军可在自己的行动中回城保兵。外军尚未回城时先选择回援或撤往另一己方城，回援时攻军可拦截或骗城；拦截依兵力、武力、统帅结算一轮损失，骗城比较有效智力，成功大幅推进，失败无损入城。
- 攻城前攻方选择围三阙一或全面包围。前者保证守军撤往另一己方城时无额外伤亡；后者默认增加 25% 城墙长度，守军突围会受损。攻城按全军最高五维及加权训练、士气计算，不再走格子。攻方撞门／蚁附／地道，守方轮换修整／修补城墙／出城袭扰，双方各下一令才结算一天。撞门稳步推进、蚁附以较大伤亡换更快推进、地道依双方智力判定；修补牺牲守军换取当前总城墙耐久恢复。
- 城墙统一为一条耐久，等级 1/2/3 默认上限 100 / 160 / 220；33% 和 66% 的突破只显示“突破瓮城／外城”等战况里程碑，不切换血条、不回复城防度。每方每轮有效兵力上限默认统一 30,000，超出者仍需粮。战损按对方有效军力算，推进按己方有效军力算。城防度越高越能减缓推进，随交战磨损；士气可打击和回复。数值与 AI 阈值均在 `rules.battle.siege`，纯规则位于 `game/siege.js`。
- 平衡基线：普通将领（五维 50）、各 10,000 普通步兵、训练 50／士气 80，相邻全力肉搏时一次行动的主动伤害约 10%，双方完成一天行动并计入反击后各损约 20%。同样军力、城防度 50、守方仅轮换修整，撞门突破一至三级城约需 8 / 13 / 18 天。三级城默认 AI 会修补，撞门约 30 天、蚁附约 17 天；这些是固定测试条件下的校准，不是任何兵力和智力配置的硬性时限。
- 野战和攻城共用累计天数、真实部队与钱粮，每个战略月推进最多 30 天，未决战役暂停后下月续战；转入攻城不重置也不重复扣当天粮。旧单将编组迁为单人部队，新城防字段由 `city-defense.js` 为剧本和旧存档补齐，升级前保留 `before-army-v1` 快照。内政“筑墙修城”默认月底完成：受损时修复城防，完好时累积扩筑，满 100 升一级，最高三级。

### 混编、军备与兵种伤亡

- 每支部队保存各兵种的真实人数，而非固定兵种或固定百分比。`game/combat-stats.js` 统一生成肉搏／远程火力与防护、行动力和视野，已计入将领、训练、士气；战斗不重复乘算。火力按人数累加，防护与机动等按编成加权；增加步兵不会稀释已有射手火力，一名射手仍可射击但杀伤很小。
- 伤亡使用 `game/troops.js` 的 `allocateTroopLosses`、`applyFormationLosses`、`applyArmyLosses`，按「当前人数 × 暴露系数」作有库存上限的整数分摊，不改变已经算出的总伤亡。大额伤亡分配到某兵种全部阵亡后，余量转由仍存活的兵种承担；每次受击后按真实剩余编成重新计算。无前后排操作或额外掩护惩罚。
- 系数在 `rules.battle.casualties.profiles`：近战步兵／重步兵／藤甲兵默认 2，近卫队 1.5，其余 1；射击分别为 1.2、1.1，其余 1；火攻与普通损耗默认均为 1。反击、伏击、攻城、拦截和突围归入近战，火矢的箭伤与引燃分别归入射击、火攻。攻城按全军兵种统一分配（包括按步兵计的预备兵），不是先按队平均；自动战斗按当日近远程贡献拆分伤亡，再使用同一分摊器。未指定／未知类型回退按人数分摊，旧存档无需补充状态。
- 良马、劲弩、甲胄是各城独立库存；内政生产及输送均沿用任务制。装备每件供一名对应士兵，出征时预留；伤亡只损失实际阵亡兵种所需装备，幸存装备随军归库，不再按全队总损失比例扣装备。
- 初始开放步兵、弓兵、重步兵、劲弩兵、骑兵；突骑兵、重骑兵、近卫队、龙骑兵、象兵、藤甲兵由议政厅内「全局政策」中的理念树解锁。改革力由势力共用，无积累上限；研习即时扣点，不消耗城市指令或武将行动。兵种、装备需求和科技都由外部规则配置，留有将领特殊解锁接口。

### 全局政策、理念组与天意循环

- 政策窗口以四列总览同时展示王、霸、正、奇的所有理念组和科技节点，不再按方向切页；前置关系使用连线与缩进显示。点击任意节点（包括尚未解锁的节点）只更新底部详情区，展示效果、装备需求、前置／后继、费用与组奖励；从详情区确认研习或回退。点击前置／后继名称可定位对应节点。天意指示常驻主界面 topbar，显示指针、阶段、改革力修正与循环强度，点击可查看完整循环与规则；无需打开政策窗口。
- 内政分 **王／霸**，军事分 **正／奇**，两条轴独立计算。王侧重收入、发展与吏治；霸侧重动员、军政与权谋；正侧重步骑、城防与补给；奇侧重弓弩、攻城、异兵和策略。目前配置 9 个理念组、27 个节点，各有明确前置依赖；六种高级兵种的解锁即时生效，其余节点明确标记“理念占位／效果待定”，暂不改变经济或战斗数值。
- 成本为 `基础费用 × (1 + 0.15 × max(0, 对立已研习数 - 本方向已研习数))`，向上取整，倍率最高 3。同一方向不打折，另一条轴不受影响；平衡发展、专注一边以及回退都会实时改变后续费用。每组全点完获得基础改革力月收入 +10；奖励从当前完整组派生，回退破坏完整组时自动失效，不存在反复完成领取一次性奖励。
- 回退不返还改革力，会连带撤销直接和间接依赖的已研习节点（也支持跨组依赖）；确认窗口列出全部受影响节点和组奖励。一次回退操作记一次“败”，自动撤销的依赖节点不重复计败。回退不改变已签发且预留资源的出征军令、现有战场兵种与装备；新编组须重新满足解锁条件。任务仅在结算其原编组时读取签发时的科技快照，不恢复势力科技，也不绕过城池归属、将领和物资检查。
- **天意循环**：新开局所有实际势力从“胜兵必骄”强度 1 开始，立即获得改革力收入 −10% 的减益，无主势力除外。取得城池、研习节点记“胜”，失去城池、回退理念记“败”。同类事件使强度 +1；反向事件清除旧增减益并从新方向强度 1 开始。非中立势力每月收入结算后再增强 1，影响下个月收入；默认最多 6 档，每档 ±10%，胜势最低收入 ×0.4，败势最高 ×1.6。箭头分别沿“哀兵必胜 → 胜兵必骄 → 骄兵必败”和“骄兵必败 → 败兵必哀 → 哀兵必胜”移动。
- 自动档、备份档与手动槽保存每个势力的 `heavenCycle`（阶段、强度、最近原因）；读取和界面渲染不会推进循环。已有明确天意的存档继续原进度（包括旧版显式中立状态），只有完全缺少天意字段的老存档补新开局起点，不追算历史战果。
- 改革力默认基础每月 100，先加完整理念组奖励，再应用天意及其他收入修正。有城池的玩家、AI 势力均结算；无主势力和已经失去所有据点的势力不产生收入。实际城池易手由统一接口记录双方胜败，含空城占领、AI 之间的战斗及多城归顺；预览、失败操作与重复战果结算不记录事件。
- `src/js/game/technology.js` 提供倾向、成本、依赖、回退和收入分解；`heaven-cycle.js` 管理胜败事件、月度推进和收入倍率；`src/data/rules.json` 的 `policyDirections`、`ideaGroups`、`technologies`、`research` 配置内容与平衡。旧档保留原点数和已解锁兵种，不补发前置节点、不追算历史胜败；首次自动存档升级保留 `:before-policies-v1` 快照。界面术语统一为“改革力”，存档仍保留 `researchPoints` / `unlockedTechnologies` 字段以兼容旧版本。

## 城池钱粮与战场补给

- 每城金粮独立，不能透支或自动借用其他城市的仓库。商业与民心决定每月金收入，农业与民心决定每年七月回合开始前的粮食收获。六月军需先结算，再进入七月收粮。
- 默认每千兵每月耗粮120，每日作战耗粮4。月底粮不够时按缺粮比例损失兵力，最多12%；按现任职位支付月俸，欠俸按缺额比例降低忠诚，最多10点。未任职在野者与俘虏不领工资，无将领城不产生人物工资，无主城不结算赋税。
- 商人有独立窗口，可从内政、城池面板、城池全览进入。买卖同价，无手续费：七、八月每金换10粮，随后每两个月少换1粮，五、六月每金换5粮，七月循环。卖粮不要求已有现金。交易需武将执行和一道指令。
- 军事指令中的「输送部队钱粮」可仅输送钱粮，不强制携兵。任意通过己方或有效盟友城池联通的己方／盟友目的地，均默认一回合抵达，不要求相邻；敌方与无主中立城池会截断路线，盟友的盟友不自动授予通行权。窗口显示经过城池，结算时再次核验通路。运输兵力为0，或至少500人且为100的倍数；金粮为非负整数。每次运输需要一名执行武将、一道指令和本城运输费，兵力抵达后按人数融合训练与士气，纯钱粮运输不改变驻军质量。
- 出征时选择携带粮食与金钱，从出发城实际扣除，另付出征费用。UI建议及最大携粮为出发兵力的 60 日口粮，但不把天数存作撤军期限；因战损减少粮耗，实际可能持续超过 60 日。每日开始按实际存活部队计算耗粮；防守方还包括城内预备兵，使用城内全部粮储。钱粮可在战斗中动态变化，消耗与天数估算随之更新。
- 缺少当天军粮立即判负；若双方同日都缺粮，攻方先撤。第 30 / 60 / 90…日结束暂停回大地图，不判守方胜、不预扣次日粮。下一月重新进入战场后才支付新一天军粮。火攻额外支付随军金，被识破也扣费，非法目标或钱不足则不扣钱与行动力。
- 撤军时余钱余粮随残军返回，攻占后随军余钱粮进入目标城并与城仓合并；守方耗用的粮与策略金写回仓库。自动战斗同样逐日重算粮耗与伤亡。
- 参数集中在 `src/data/rules.json` 的 `economy`、`actions`、`battle`；纯经济逻辑在 `src/js/game/economy.js`，可复用的交易窗口在 `src/js/ui/economy-windows.js`。
- 旧存档原钱粮不重置、不补发过去收入；升级前保存同名 `:before-economy-v2` 快照。旧的待处理出征从其有效出发城实际划拨补给一次，不凭空创造资源。新的玩家出征作为任务保存已划出的部队与补给，进入战役后由完整快照继续维护，刷新不会重开或再次划拨。

## 持续战役与后台模拟

- 顶部「战役簿」列出我方及 AI 间的所有战场，可查看阶段、累计天数、兵力、城墙进度和近期战报，定位地图上的交战城池。玩家战报沿用视野权限，不展示敌军隐蔽动作；AI 战争只提供概况，不打开操作战场。
- 每场战役有独立 ID、月度进度及结算版本。`game/war-campaigns.js` 负责建战、检查点、逐月调度和最终归库，`game/war-state.js` 负责参战锁定、围城与口粮账目；同一城市本版只承受一场围攻，多地可同时交战。
- `BattleEngine.snapshot()` 输出纯 JSON，`BattleEngine.fromSnapshot()` 恢复地图、部队、兵种、AP、队列、迷雾、持续状态、金粮、随机种子及攻城指令；不重新部署，不重扣当天粮。结算版本防止旧实例覆盖新进度，最终战果只应用一次。旧攻城分层快照迁移成等比例单条耐久。结束战役压缩为兵力／钱粮／城墙摘要及最近 36 条战报，不继续保存地图和完整引擎，避免长线存档重复膨胀。
- `game/battle-simulation.js` 的 `simulateBattleMonth` 不依赖 DOM、动画或计时器，直接驱动双方调用与玩家相同的移动、视野、ZOC、伏击、策略、伤亡、攻城和供粮规则。表现层仅负责输入与显示；不另写一套 AI 对 AI 的简化胜负公式。
- 出征将领在整场战争期间锁定，跨月不能重复派遣或被作为城内守将俘虏；围城城市暂不接受内政、征募、运输、调任或第二支进攻军，运输也不能穿过交战城池。本版未添加中途增援／补给军／解围会战。
- 守城钱粮在战斗切片结束后同步回城市，月税、俸禄及七月粮收仍正常结算，再同步至下月战场；外征将领仍由所属城市支付俸禄，原城失守且无所属城时才从随军金支付，欠俸降低忠诚。驻军粮按实际战场供粮天数抵扣，提前归城的部队仍支付剩余日数的驻军粮。双方归库及装备损耗只结算一次。

## 任务制与月度流程

玩家当前的内政、征兵、训练、任命、寻访、登用、迁任、外交、商人买卖、运输和出征默认都在结束本月后生效，不再签发后立即完成。提交时立即占用一道指令、执行武将，并把所需金粮／兵员从可用库存划入任务预留；到期结算不再重复扣除。运输到货和商人交易在月末维护之前完成，因此可用于补充当月军需。商人任务采用签发时确认的粮价。

- 顶部「任务簿」分别展示正在执行、本回合刚完成及往期任务，包含执行者、起止城池、剩余回合、结果或失败原因。
- 多回合任务期间武将持续忙碌，过月不会清除任务占用；一次签发只扣一次指令。结算前再次检查执行者、城池归属及行动条件。任务失效且出发城仍属原势力时，预留资源退回原城；已失守时不把预留资源退入敌方仓库，也不挪入其他城池。已经使用的指令不返还。
- 规则层 `src/js/game/tasks.js` 提供 `queueTask`、`settleTasks`、`getReadyBattleTask`、`finishBattleTask` 等接口，复用现有行动规则。任务按签发顺序结算；出征进入战役后标记为「跨月作战中」，不阻挡其他到期任务，在战役真正结束时才记录任务完成结果。
- 完成时机位于 `src/data/rules.json` 的 `tasks`：`defaultTiming` 目前为 `turn_end`，`actions` 可按任务类别覆盖。支持 `immediate`（立即完成）、`turn_end`（本月结束后完成）和 `multi_turn`（`duration` 个回合后完成）。下面仅为扩展示例，当前配置并未启用这些例外：

```json
{
  "tasks": {
    "defaultTiming": "turn_end",
    "actions": {
      "trade": { "timing": "immediate" },
      "domestic": { "timing": "multi_turn", "duration": 3 }
    }
  }
}
```

`src/js/game/turn-flow.js` 的持续战役流程分为可保存的 `tasks`（到期任务及建战）、`world`（AI 行动）、`invasions`（选择来袭应对）、`battles`（完成所有本月战斗切片）、`economy`（统一经济及递进月份）、`opening`（新回合汇报）。回合编号、AI 月份标记及战役处理月份防止刷新或重复调用导致收入、维护和作战重复结算。任一阶段中断后均从检查点继续；月初汇报结束后清除月结检查点，未决战役保留。旧存档自动补齐任务及战役字段，不重置经营进度。

## 剧情与回合开场

`src/js/ui/story-dialog.js` 提供通用 `showStoryDialog`：可传人物姓名与可选本地头像，亦可省略人物作为旁白；支持多页文字，点击、Enter或空格继续。尚无人物头像时显示姓名印记，不增加虚构人物或访问远程素材。

每回合开始使用同一个窗口报告轮到本势力行动及可用指令数；优先由剧本内真实君主出面，没有可用君主时使用旁白。同一月份已阅读的汇报不会因普通刷新重复弹出。

若上月有完成或失败的任务，月初对白结束后自动弹出「月初任务结算」，涵盖内政、运输以及已经处理完的出征结果。空结果不弹；多回合任务等真正完成再汇报。结算阅读状态随存档保存，同一月份读档不重复弹出，仍可从「任务簿 → 本月结算」手动复查。

## 区域城市主题图

`src/data/city-themes.json` 将地图区域映射到中原、北地、西北、江南、西南五套共用场景，位于 `src/assets/cities/`，用内置图像生成工具生成；提示词保存在同目录 `prompts.json`。场景是区域气氛图而非单城精确复原，不随武将数量增加图像成本。点击城市面板顶部城景可打开城池全览，武将头像暂使用统一占位图。

## 验证与扩展

运行 `npm test` 检查规则、地图、存档与剧本完整性。独立规则测试使用 `tests/fixtures/legacy-scenario.json`，避免修改剧本配置时破坏测试前提。`src/js/game/campaign.js` 提供纯状态函数；`src/js/ui/campaign-windows.js` 提供独立操作窗口，可复用于地图、列表或未来快捷入口。

政策交互另有 `artifacts/policy-qa.html`：先 `npm run build`，再从项目根目录用 `python3 -m http.server 4175 --bind 127.0.0.1` 启动本地服务器，访问 `/artifacts/policy-qa.html`。它使用真实政策界面与规则、内存内的 5,000 改革力测试势力，支持推进月份、得失城池与序列化恢复，不读写正式游戏存档。

## 界面主题

`src/styles/classic-theme.css` 是独立的表现层：青灰绢底、暖纸面板、青铜压边与回云角花，参考三国志7—10时期的古朴窗口气质，不使用原游戏素材。`src/assets/ui/` 保存四个原创、小体积SVG纹样，颜色与表面材质变量集中在主题文件顶部。修改主题不需要修改游戏规则。

战略界面继续使用浮动窗口；城市面板与政令区共享定位变量以避免相互遮挡。野战背景覆盖战场，正面错列的正方形棋盘按可用宽高等比缩放居中，浮窗不参与棋盘尺寸计算，可收起浮窗操作被遮住的地块。行动按钮固定可见，战报独立滚动。人物窗口在窄屏切换列布局。所有纹样不拦截点击，且尊重系统的减少动画设置。

所有页面、数据与美术均在本地读取，没有站点发布、在线地图或远程存档依赖。
